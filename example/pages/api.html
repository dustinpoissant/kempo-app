API

api is a global available everywhere — renderer scripts, page fragments, backend.js, init.js, and update.js. The framework sets it up on both window (renderer) and global (main process) so you can use api.* without a prefix in any context.

Database

See the Database docs for full details.

api.jsonDB(table)

Returns a table handle for the file-based JSON database. Each table is stored as a separate JSON file. The handle provides .get(), .set(), .delete(), .has(), and .clear() methods — all async. See JSON DB docs. 

const settings = api.jsonDB('settings');
await settings.get() // all keys
await settings.get('theme') // one value
await settings.set('theme', 'dark')
await settings.delete('theme')
await settings.has('theme') // true / false
await settings.clear()
api.sqlQuery(db, sql)

Run a raw SQL query against a named SQLite database. Requires better-sqlite3 in the consumer project. SELECT returns an array of row objects; everything else returns true. Throws on error. See SQL DB docs. 

await api.sqlQuery('mydb', 'CREATE TABLE IF NOT EXISTS users (id INTEGER PRIMARY KEY, name TEXT)')
await api.sqlQuery('mydb', "INSERT INTO users (name) VALUES ('Alice')") // true
await api.sqlQuery('mydb', 'SELECT * FROM users') // [{ id, name }, ...]

Window

api.window.minimize()

Minimize the current window to the taskbar / dock.

api.window.minimize();
api.window.maximize()

Toggle between maximized and restored window state.

api.window.maximize(); // toggles maximize / restore
api.window.close()

Close the current window. If it is the last window, the app quits (on Windows/Linux).

api.window.close();
api.window.new(options?)

Open a new app window. Pass nothing for defaults, a hash string for a specific route, or an options object to customize the shell, titlebar, or pages directory for that window. 

// Open a new window (uses default shell)
api.window.new();
// Open at a specific route
api.window.new('#/settings');
// Open with a different shell
api.window.new({
  hash: '#/editor',
  shell: 'editor-shell.html'
});
// Open with no titlebar
api.window.new({
  hash: '#/viewer',
  titlebar: false
});

The shell file is an HTML fragment that must contain an <app-page> element for the router to render pages into.

Notifications

Use api.notification instead of the browser's Notification API. Because the renderer runs in a sandboxed context, the framework routes notifications through IPC to the main process, which uses Electron's native Notification class to ensure they are always delivered to the OS.

api.notification.show(opts)

Show a native OS notification. Returns a notification ID that can be used to identify which notification the user interacted with. 

const id = await api.notification.show({
  title: 'Download Complete',
  body: 'report.pdf has been saved.',
  icon: 'media/icon.png'
});

All options:

Option Type Description
titlestringNotification title. Defaults to the app name.
bodystringNotification body text.
iconstringApp-root-relative image path. Defaults to the app icon.
silentbooleanSuppress the OS notification sound.
subtitlestringSecondary line below the title. macOS only.
urgency"normal" | "critical" | "low"Notification priority. Linux only.
timeoutType"default" | "never"Controls auto-dismiss. Linux and Windows only.

React to user interactions by listening for events on window:

window.addEventListener('notification:click', e => {
  console.log('clicked', e.detail.id);
});
window.addEventListener('notification:close', e => {
  console.log('dismissed', e.detail.id);
});
// macOS inline reply
window.addEventListener('notification:reply', e => {
  console.log(e.detail.id, e.detail.reply);
});
Event Fired when event.detail
notification:clickUser clicks the notification{ id }
notification:closeNotification is dismissed{ id }
notification:replyUser submits inline reply (macOS){ id, reply }

Returns true if the current platform supports notifications.

const supported = await api.notification.isSupported();

    title: 'Hello'

File System

api.fs provides async access to the local file system. All methods use absolute paths and return promises. Encoding defaults to "utf-8" for text operations — pass null to read raw binary data.

api.fs.readFile(path, encoding?)

Read a file's contents. Defaults to UTF-8 text. Pass null for binary.

const content = await api.fs.readFile('/path/to/file.txt');
const binary = await api.fs.readFile('/path/to/image.png', null);
api.fs.writeFile(path, data, encoding?)

Write data to a file, replacing it if it already exists.

await api.fs.writeFile('/path/to/file.txt', 'Hello, world!');
api.fs.appendFile(path, data, encoding?)

Append data to the end of a file. Creates the file if it doesn't exist.

await api.fs.appendFile('/path/to/log.txt', 'New entry\n');
api.fs.readDir(path)

List the contents of a directory. Returns an array of filenames.

const files = await api.fs.readDir('/path/to/directory');
// ['file1.txt', 'file2.txt', 'subfolder']
api.fs.mkdir(path, options?)

Create a directory. Pass { recursive: true } to create nested directories.

await api.fs.mkdir('/path/to/new/nested/dir', {
  recursive: true
});
api.fs.rm(path, options?)

Remove a file or directory. Pass { recursive: true, force: true } for directories.

await api.fs.rm('/path/to/file.txt');
await api.fs.rm('/path/to/directory', {
  recursive: true,
  force: true
});
api.fs.exists(path)

Check whether a file or directory exists. Returns true or false.

if (await api.fs.exists('/path/to/file.txt')) {
  // file exists
}
api.fs.stat(path)

Get metadata about a file or directory.

const info = await api.fs.stat('/path/to/file.txt');
// { size, isFile, isDirectory, isSymbolicLink, createdAt, modifiedAt, accessedAt }
Property Type Description
sizenumberFile size in bytes
isFilebooleanTrue if path is a regular file
isDirectorybooleanTrue if path is a directory
isSymbolicLinkbooleanTrue if path is a symbolic link
createdAtstringISO 8601 creation timestamp
modifiedAtstringISO 8601 last-modified timestamp
accessedAtstringISO 8601 last-accessed timestamp
api.fs.rename(oldPath, newPath)

Rename or move a file or directory.

await api.fs.rename('/path/to/old.txt', '/path/to/new.txt');
api.fs.copyFile(src, dest)

Copy a file from one path to another.

await api.fs.copyFile('/path/to/source.txt', '/path/to/dest.txt');

Custom API Routes

Define custom backend functions by creating an api/ directory in your app root. Each .js file in api/ is automatically registered as a callable function. This is the primary way to extend kempo-app with custom backend logic.

Creating Custom API Functions

Create an api/ directory and add a file for each function:

api/
  runCommand.js     → await window.api.runCommand()
  getFile.js        → await window.api.getFile()
  saveData.js       → await window.api.saveData()

Each file must export a default async function:

// api/runCommand.js
import { execSync } from "child_process";

export default async function runCommand(cmd, ...args) {
  try {
    const output = execSync(`${cmd} ${args.join(' ')}`, { encoding: "utf8" });
    return { success: true, output };
  } catch (error) {
    return { success: false, error: error.message };
  }
}
Calling from Frontend

Call custom API functions just like built-in ones:

const result = await api.runCommand("ls", "-la");
console.log(result); // { success: true, output: "..." }
Error Handling

If a custom function throws an error, the promise rejects:

try {
  const result = await api.runCommand("invalid-cmd");
} catch (error) {
  console.error("Backend error:", error.message);
}
Full Backend Access

Your custom functions have full Node.js access:

// api/getFile.js — read files
import { readFileSync } from "fs";
export default async function(filePath) {
  return readFileSync(filePath, "utf8");
}
// api/saveData.js — write files
import { writeFileSync } from "fs";
export default async function(filePath, content) {
  writeFileSync(filePath, content, "utf8");
  return { saved: true };
}

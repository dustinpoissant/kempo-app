Components

kempo-app is built on kempo-ui — a library of Web Components with a k- prefix. Import what you need in app.js: 

import "/modules/kempo-ui/dist/components/Card.js";
import "/modules/kempo-ui/dist/components/Toggle.js";
import "/modules/kempo-ui/dist/components/Tabs.js";
// ...

See the kempo-ui docs →

App Components

The framework provides <app-*> components automatically — no imports needed.
These handle titlebar, page routing, and conditional visibility.

<app-titlebar> — A custom titlebar for window managment.

The kempo-app is rendered as a frameless window, so to add support for window managment (dragging, minimize, maximize, and close) kempo-app provides a custom <app-titlebar component.

Content is placed into the titlebar via slots:

Slot Position
left After traffic lights (Mac) or at the start (Win/Linux)
default Center — replaces the app name title
right Before window controls (Win/Linux) or at the end (Mac)

The entire titlebar is draggable. Add class="no-drag" to interactive elements (buttons, dropdowns, switchers) so they remain clickable.

titlebar.html

Place the <app-titlebar> in titlebar.html:

<app-titlebar>
  <k-dropdown slot="left" class="no-drag">...</k-dropdown>
  <b>My App</b>
  <k-theme-switcher slot="right" class="no-drag"></k-theme-switcher>
</app-titlebar>

<app-page> — Where the page content is rendered.

This is the location where the page's content will be rendered when the hash router updates.

<app-page></app-page>

<app-show> / <app-hide> — Conditional content rendering.

Conditionally show or hide content based on runtime conditions. <app-show> renders its children when all conditions match. <app-hide> hides its children when all conditions match.

Attribute Values Description
platform mac, win, linux Match OS platform
dev (boolean) Match dev mode
theme light, dark Match current theme (reactive)
maximized (boolean) Match window maximized state (reactive)
setting key or key=value Match a database setting
Examples

platform — show based on OS

Visible on macOS Hidden on macOS Visible on Windows Hidden on Windows Visible on Linux Hidden on Linux 
<app-show platform="mac">Visible on macOS</app-show>
<app-hide platform="mac">Hidden on macOS</app-hide>
<app-show platform="win">Visible on Windows</app-show>
<app-show platform="linux">Visible on Linux</app-show>

dev — show based on dev mode

Dev mode Production mode 
<app-show dev>Dev mode</app-show>
<app-hide dev>Production mode</app-hide>

theme — show based on current theme (reactive)

Light theme Dark theme 
<app-show theme="light">Light theme</app-show>
<app-show theme="dark">Dark theme</app-show>

maximized — show based on window maximized state (reactive)

Window is maximized Window is not maximized 
<app-show maximized>Window is maximized</app-show>
<app-hide maximized>Window is not maximized</app-hide>

setting — show based on a database value (reactive)

notifications = truthy notifications = falsy theme = "dark" 
<!-- truthy check -->
<app-show setting="notifications">notifications is enabled</app-show>
<app-hide setting="notifications">notifications is disabled</app-hide>
<!-- exact value check -->
<app-show setting="theme=dark">dark theme setting</app-show>

<app-setting-bool> / <app-setting-string> / <app-setting-number> — Persistent settings inputs.

These components bind a form control to a database key via the setting attribute. The value is loaded from the database on connect and saved automatically on change. Each change dispatches a settingchange event on window.

Component Renders Value type
<app-setting-bool> <k-toggle> Boolean
<app-setting-string> <input type="text"> String
<app-setting-number> <input type="number"> Number
Attribute Description
setting Database key to read/write

Slotted content is rendered as a label.

Examples
<app-setting-bool setting="notifications">Enable Notifications</app-setting-bool>
<app-setting-string setting="username">Username</app-setting-string>
<app-setting-number setting="fontSize">Font Size</app-setting-number>

Testing

kempo-app ships shared test infrastructure so you can write browser tests for your components and pages without Electron. Install kempo-testing-framework as a dev dependency and you're ready to go.

Setup

npm install --save-dev kempo-testing-framework

Add a test script to your package.json:

{
  "scripts": {
    "test": "npx kempo-test"
  }
}

Create a tests/ directory — the runner discovers test files recursively.

The Test Page

kempo-app provides a ready-made test page at /node_modules/kempo-app/testing/test-page.html. It mocks the Electron environment so your components work in a plain browser:

What Purpose
Import mapRemaps /modules/ and /framework/ to node_modules/ paths
window.api mockIn-memory DB, no-op window controls, platform stubs
window.kempoBrowser-relative paths to kempo-css and icon directories

Writing a Browser Test

Create a .browser-test.js file in tests/. Export page to point at the shared test page, use beforeAll for dynamic imports, and export a default object of test functions: 

export const page = "/node_modules/kempo-app/testing/test-page.html";

export const beforeAll = async () => {
  await import("/modules/kempo-ui/dist/components/Card.js");
};

export default {
  "card renders content": async ({ pass, fail }) => {
    const card = document.createElement("k-card");
    card.label = "Test";
    card.innerHTML = "<p>Hello</p>";
    document.body.appendChild(card);
    await card.updateComplete;
    if(card.shadowRoot.querySelector("slot")) pass();
    else fail("No slot found");
    card.remove();
  }
};

No Top-Level Imports

Test files are parsed by Node.js (to extract the page export) before running in the browser. Top-level import statements with /framework/ or /modules/ paths will fail in Node. Always use dynamic import() inside beforeAll: 

// BAD — fails when Node parses the file
import "/modules/kempo-ui/dist/components/Icon.js";

// GOOD — runs only in the browser
export const beforeAll = async () => {
  await import("/modules/kempo-ui/dist/components/Icon.js");
};

Lifecycle Hooks

Tests support four lifecycle hooks, all optional:

Hook Runs
beforeAllOnce before all tests — import components here
afterAllOnce after all tests
beforeEachBefore each test — reset DOM/state
afterEachAfter each test — cleanup

Node Tests

For logic that doesn't need a browser (pure functions, data utilities), create .node-test.js files instead. Same test function signature, no page export needed: 

export default {
  "adds numbers": ({ pass, fail }) => {
    if(1 + 1 === 2) pass();
    else fail("Math is broken");
  }
};

Running

npm test

The runner discovers all .browser-test.js and .node-test.js files in tests/ recursively, runs them, and prints a summary.

Mock API Surface

The window.api mock in testing/mocks.js matches the full preload.cjs API. The in-memory db store is accessible via window.__kempoTestDbStore for direct inspection in tests: 

// Seed the store before a test
window.__kempoTestDbStore.username = "alice";

// Read it through the API
const val = await window.api.db.get("username"); // "alice"

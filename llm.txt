# kempo-app — LLM Reference

kempo-app is an npm package that turns a folder of HTML fragments into an Electron desktop app with zero boilerplate.
Docs: https://dustinpoissant.github.io/kempo-app/

## IMPORTANT — Read These First

This project uses kempo-ui (components) and kempo-css (styles/utilities). Before writing any code, fetch and read both of these files:

- kempo-ui: https://raw.githubusercontent.com/dustinpoissant/kempo-ui/refs/heads/main/llm.txt
- kempo-css: https://raw.githubusercontent.com/dustinpoissant/kempo-css/refs/heads/main/llms.txt

NEVER create a custom component if kempo-ui already has one. NEVER write custom CSS for something kempo-css covers. Always check both files first.

## Install & Run

```sh
npm install kempo-app
```

Create `pages/index.html` — the only required file:

```html
<h1>Hello World</h1>
```

```sh
npx kempo-app       # run the app
npx kempo-app --dev # run with DevTools + CDP on port 9222
```

package.json scripts:
```json
"scripts": {
  "start": "kempo-app",
  "dev": "kempo-app --dev",
  "interact": "kempo-interact",
  "test": "npx kempo-test"
}
```

## Project Structure

| File | Required | Description |
|------|----------|-------------|
| `package.json` | yes | Configure app via `kempo-app` field |
| `pages/index.html` | yes | Home page fragment, loaded for `#/` |
| `pages/<name>.html` | no | Additional pages, loaded for `#/<name>` |
| `shell.html` | no | Nav + `<app-page>` shell (default is bare `<app-page>`) |
| `titlebar.html` | no | Place `<app-titlebar>` here |
| `app.js` | no | ESM module — import kempo-ui components, run startup logic |
| `theme.css` | no | CSS variable overrides, loaded after kempo-css |
| `backend.js` | no | Runs in Electron main process every startup |
| `init.js` | no | Runs once on first launch |
| `update.js` | no | Runs when package.json version changes |
| `icons/` | no | Custom SVG icons (override built-in icons) |
| `media/` | no | App assets (icon.png, etc.) |
| `schema/` | no | SQL table definitions — auto-created and auto-migrated |

### package.json config

All framework config lives in the `kempo-app` field:

```json
{
  "kempo-app": {
    "appName": "My App",
    "appIcon": "media/icon.png",
    "protocolName": "my-app",
    "shell": "shell.html",
    "titlebar": "titlebar.html",
    "pages": "pages"
  }
}
```

| Key | Default | Description |
|-----|---------|-------------|
| `appName` | `name` field or `"Kempo App"` | Window title and display name |
| `appIcon` | none | Path to icon relative to project root |
| `protocolName` | `"kempo-app"` | Custom protocol scheme, registered with OS |
| `shell` | `"shell.html"` | Default shell HTML for new windows |
| `titlebar` | `"titlebar.html"` | Titlebar HTML, `true` for default, `false` to disable |
| `pages` | `"pages"` | Directory containing page HTML fragments |

## shell.html

The app shell — defines persistent UI around page content. Must contain `<app-page>` for the router.

```html
<nav class="bg-alt px bb">
  <a href="#/" class="nav-link">Home</a>
  <a href="#/settings" class="nav-link">Settings</a>
</nav>
<app-page class="flex-1 p"></app-page>
```

If omitted, the default shell is just `<app-page></app-page>`.

## Routing

Hash routes map directly to `pages/` files. No config needed.

| Hash | File |
|------|------|
| `#/` | `pages/index.html` |
| `#/settings` | `pages/settings.html` |
| `#/any-name` | `pages/any-name.html` |
| `#/sub/path` | `pages/sub/path.html` |

Query params: `#/settings?tab=theme` → `window.route.params.tab === "theme"`

`window.route` is always available: `{ path, params }`.

Listen for navigation:
```js
window.addEventListener("routechange", e => {
  console.log(e.detail.path, e.detail.params);
});
```

External links: `target="_blank"` or `window.open()` → opens in system browser.

New app window:
```js
api.window.new();                    // default shell at #/
api.window.new("#/settings");        // specific route
api.window.new({ hash: "#/editor", shell: "editor-shell.html" }); // different shell
api.window.new({ hash: "#/viewer", titlebar: false });             // no titlebar
```

## Pages

Pages are HTML fragments (no `<html>/<head>/<body>`). Any `<script>` in a fragment runs after it renders.

```html
<!-- pages/index.html -->
<h1>Home</h1>
<button id="btn">Click me</button>
<script>
document.getElementById("btn").addEventListener("click", () => alert("clicked"));
</script>
```

Use `<script type="module">` for imports within page scripts.

## API

`api` is a global available everywhere — renderer scripts, page fragments, `backend.js`, `init.js`, `update.js`. Set up on both `window` (renderer) and `global` (main process).

### Database — api.jsonDB

File-based JSON key/value store. Each table = a separate JSON file. No setup needed.

```js
const settings = api.jsonDB("settings");
await settings.get()            // all keys → { key: value, … }
await settings.get("theme")     // one value
await settings.set("theme", "dark")
await settings.delete("theme")
await settings.has("theme")     // true / false
await settings.clear()          // wipe table
```

Tables auto-created on first write. Values can be any JSON-serializable type.

Every `set()` fires `jsondb_change:{table}` on `window`:
```js
window.addEventListener("jsondb_change:settings", e => {
  console.log(e.detail.key, e.detail.value);
});
```

### Database — SQL (DB class)

Full SQL database via better-sqlite3. Requires `npm install better-sqlite3`.

```js
import DB from "/framework/src/renderer/utils/sqlDB.js";

const db = new DB("mydb");
const users = db.table("users");

// Create
const record = await users.create({ name: "Alice", email: "alice@example.com" });
record.data // { id: 1, name: "Alice", email: "alice@example.com" }

// Read
const all = await users.getAll();           // Record[]
const user = await users.get({ id: 1 });    // Record or null
const last = await users.getLast();          // Record or null
const filtered = await users.getAll({ name: "Alice" }); // Record[]

// Update & Delete via Record
await user.update({ name: "Alicia" });
await user.delete();

// Bulk operations via Table
await users.update({ name: "Alice" }, { name: "Alicia" });  // first match
await users.updateAll({ active: 0 }, { active: 1 });        // all matches
await users.delete({ id: 5 });      // first match
await users.deleteAll({ active: 0 }); // all matches

// Raw SQL
await db.query("SELECT * FROM users WHERE age > 21"); // rows array
await db.query("DROP TABLE temp");                     // true
```

Record objects: `record.data` (row object), `record.update(data)`, `record.delete()`.

DB class works identically in `backend.js` — same import, same API.

### Database — Raw SQL (api.sqlQuery)

**Advanced usage only** — for complex queries the DB class can't express (joins, subqueries, aggregations). If it can be done with `DB`/`Table`/`Record`, use those instead. Use `schema/` files for creating and altering tables whenever reasonably possible — they handle versioning and migrations automatically.

```js
await api.sqlQuery("mydb", "SELECT u.name, COUNT(o.id) as orders FROM users u JOIN orders o ON o.user_id = u.id GROUP BY u.id");
```

SELECT returns array of rows; everything else returns `true`; throws on error.

### Storage Location

| Platform | Path |
|----------|------|
| Windows | `%APPDATA%\<appName>\db\` |
| macOS | `~/Library/Application Support/<appName>/db/` |
| Linux | `~/.config/<appName>/db/` |

JSON tables = `*.json`, SQL databases = `*.db`.

```js
api.window.minimize()
```

### Notifications

Use `api.notification` instead of browser `Notification` API (sandboxed context routes through IPC to main process).

```js
const id = await api.notification.show({
  title: "Download Complete",
  body: "report.pdf has been saved.",
  icon: "media/icon.png",    // optional, defaults to app icon
  silent: false,              // optional
  subtitle: "...",            // macOS only
  urgency: "normal",         // Linux only: "normal" | "critical" | "low"
  timeoutType: "default"     // Linux/Windows: "default" | "never"
});

const supported = await api.notification.isSupported();
```

Notification events on `window`:
```js
window.addEventListener("notification:click", e => console.log(e.detail.id));
window.addEventListener("notification:close", e => console.log(e.detail.id));
window.addEventListener("notification:reply", e => console.log(e.detail.id, e.detail.reply)); // macOS
```

### Utilities

```js
await api.getPlatform()    // "mac" | "win" | "linux"
await api.getAppName()     // configured app name
await api.isDev()          // true if --dev flag
```

## Schema Tables

Define SQL tables as files — no SQL needed. Auto-created on first startup, auto-migrated when schema changes.

Directory structure:
```
schema/
  mydb/           ← database name
    contacts.js   ← table name
    settings.js
```

Schema file format:
```js
// schema/mydb/contacts.js
export default {
  name: { type: "text", required: true },
  email: { type: "text", unique: true },
  phone: { type: "text" },
  age: { type: "integer" },
  score: { type: "real", default: 0 },
};
export const version = 1;
```

If no column has `primary: true`, the table auto-gets `id INTEGER PRIMARY KEY AUTOINCREMENT`.

Custom primary key:
```js
export default {
  key: { type: "text", primary: true },
  value: { type: "text" },
};
export const version = 1;
```

Column options:

| Option | Description |
|--------|-------------|
| `type` | `"text"`, `"integer"`, `"real"`, `"blob"` (default: `"text"`) |
| `primary` | Makes this the primary key (integer PKs get AUTOINCREMENT) |
| `required` | Adds NOT NULL |
| `unique` | Adds UNIQUE |
| `default` | Default value |
| `index` | Creates secondary index |

### Auto-Migration

On every startup, the framework compares schema files against the database. Missing tables are created, missing columns added via ALTER TABLE. Existing columns are never removed or modified.

### Versioning

For changes beyond adding columns (rename, transform, drop), bump `version` and add `updates`:

```js
export default {
  name: { type: "text", required: true },
  email: { type: "text", unique: true },
  display_name: { type: "text" },
};
export const version = 3;
export const updates = [
  null,           // v1→v2: auto-migrate only
  (db) => {       // v2→v3: custom migration
    db.exec("ALTER TABLE contacts RENAME COLUMN username TO display_name");
    return true;  // also run auto-migrate after
  },
];
```

Rules:
- `updates[0]` = v1→v2, `updates[1]` = v2→v3, etc.
- `updates.length` should equal `version - 1`
- `null` entry = auto-migrate only
- Function entry called with `(db)`, return `true` to also auto-migrate after
- New tables skip all updates, created at latest version

## Components

### App Components (auto-imported, no import needed)

**`<app-page>`** — router render target. Place in `shell.html`.

**`<app-titlebar>`** — frameless window titlebar with drag support. Slots: `left`, default (center), `right`. Add `class="no-drag"` to interactive elements.

```html
<app-titlebar>
  <b>My App</b>
  <k-theme-switcher slot="right" class="no-drag"></k-theme-switcher>
</app-titlebar>
```

**`<app-show>` / `<app-hide>`** — conditional rendering. All conditions must match.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `platform` | `mac`, `win`, `linux` | Match OS |
| `dev` | boolean | Match dev mode |
| `theme` | `light`, `dark` | Match current theme (reactive) |
| `maximized` | boolean | Match window state (reactive) |
| `setting` | `key` or `key=value` | Match jsonDB settings value (reactive) |

```html
<app-show platform="win">Windows only</app-show>
<app-hide dev>Production only</app-hide>
<app-show setting="notifications">Notifications enabled</app-show>
<app-show setting="theme=dark">Dark theme active</app-show>
```

**`<app-setting-bool>`** — toggle bound to jsonDB setting:
```html
<app-setting-bool setting="notifications">Enable Notifications</app-setting-bool>
```

**`<app-setting-string>`** — text input bound to jsonDB setting:
```html
<app-setting-string setting="username">Username</app-setting-string>
```

**`<app-setting-number>`** — number input bound to jsonDB setting:
```html
<app-setting-number setting="fontSize">Font Size</app-setting-number>
```

All setting components auto-load from the database on connect and save on change. Slotted content is the label.

## Theming

Create `theme.css` in project root. Loaded after kempo-css, so overrides win. Light/dark handled automatically via `light-dark()`.

```css
:root {
  --c_primary: #47848F;
  --c_primary__hover: #3a6b74;
  --c_input_accent: #47848F;
  --c_highlight: rgba(71, 132, 143, 0.2);
}
```

Key variables:

| Variable | Controls |
|----------|----------|
| `--c_primary` | Buttons, links, active nav, focus rings |
| `--c_primary__hover` | Hover state for primary elements |
| `--c_input_accent` | Input focus + toggle active color |
| `--c_bg` | Page background |
| `--c_bg__alt` | Nav, sidebar, card backgrounds |
| `--c_border` | Borders |
| `--tc` | Base text color |
| `--radius` | Border radius |
| `--spacer` | Base spacing unit |

## Backend

Three optional files run in Electron's main process:

| File | When | Context |
|------|------|---------|
| `backend.js` | Every startup | `{ ipc, app, Menu }` |
| `init.js` | Once on first launch | `{ ipc, app, Menu }` |
| `update.js` | When version changes | `{ ipc, app, Menu, from, to }` |

Startup sequence:
1. Framework init (JSON DB + SQL DB available)
2. `init.js` (first launch) or `update.js` (version change)
3. Schema sync (create/migrate tables from `schema/`)
4. Custom API registration (from `api/` directory)
5. `backend.js`
6. Window creation

```js
// backend.js
export default ({ ipc, app, Menu }) => {
  // Custom IPC
  ipc.handle("my-channel", async (e, data) => {
    return await api.jsonDB("settings").get("someKey");
  });

  // Deep links — protocolName:// links
  app.on("open-link", url => {
    const parsed = new URL(url);
    console.log(parsed.pathname, parsed.searchParams);
  });

  // File associations
  app.on("open-path", filePath => {
    console.log("Open file:", filePath);
  });

  // Cleanup
  app.on("before-quit", () => {
    api.jsonDB("settings").set("lastSession", Date.now());
  });
};
```

### Custom API Routes

Create an `api/` directory to define custom backend functions callable from the frontend. Each `.js` file in `api/` automatically exports a function accessible via `window.api.functionName()`.

**Directory structure:**
```
api/
  runCommand.js     → await window.api.runCommand()
  getFile.js        → await window.api.getFile()
  saveData.js       → await window.api.saveData()
```

**API file format:**

Each file must export a default async function. It receives arguments from the frontend call and returns a value.

```js
// api/runCommand.js
import { execSync } from "child_process";

export default async function runCommand(cmd, ...args) {
  try {
    const output = execSync(`${cmd} ${args.join(" ")}`, { encoding: "utf8" });
    return { success: true, output };
  } catch (error) {
    return { success: false, error: error.message };
  }
}
```

```js
// api/getFile.js
import { readFileSync } from "fs";

export default async function getFile(filePath) {
  return readFileSync(filePath, "utf8");
}
```

```js
// api/saveData.js
import { writeFileSync } from "fs";

export default async function saveData(filePath, content) {
  writeFileSync(filePath, content, "utf8");
  return { saved: true };
}
```

**Calling from frontend:**

```js
// pages/index.html or app.js
const result = await window.api.runCommand("ls", "-la");
console.log(result);

const fileContent = await window.api.getFile("/path/to/file.txt");

await window.api.saveData("/path/to/file.txt", "new content");
```

**Error handling:**

If a backend function throws an error, the promise rejects with the error message. Wrap calls in try/catch:

```js
try {
  const result = await window.api.runCommand("invalid-cmd");
} catch (error) {
  console.error("Backend error:", error.message);
}
```

**Key patterns:**

- Files are loaded on startup — restart the app to pick up new files
- Only `.js` files in `api/` are loaded; subdirectories are ignored
- API function names are case-sensitive (file `myFunc.js` → `window.api.myFunc()`)
- Functions can be async or sync (always return a Promise to frontend)
- Full Node.js access: `fs`, `child_process`, database, CLI tools, etc.
- Use this for CLI wrappers, file operations, background tasks, anything the frontend can't do

### Context Menu

Auto-shows native context menu on right-click (Cut/Copy/Paste on inputs, Copy on selected text, Inspect in dev mode).

Add custom items:
```js
api.contextMenu.onClick(id => {
  if(id === "delete") handleDelete();
});

element.addEventListener("contextmenu", () => {
  api.contextMenu.show([
    { id: "rename", label: "Rename" },
    { id: "delete", label: "Delete" },
  ]);
});
```

### Mac Menu Bar

```js
export default ({ app, Menu }) => {
  if(process.platform !== "darwin") return;
  const menu = Menu.buildFromTemplate([
    { label: app.getName(), submenu: [{ role: "about" }, { type: "separator" }, { role: "quit" }] },
    { label: "File", submenu: [{ label: "New Window", accelerator: "CmdOrCtrl+N" }, { role: "close" }] },

  ]);
  Menu.setApplicationMenu(menu);
};
```

## Testing

```sh
npm install --save-dev kempo-testing-framework
```

Browser test files (`.browser-test.js`):
```js
export const page = "/node_modules/kempo-app/testing/test-page.html";

export const beforeAll = async () => {
  await import("/modules/kempo-ui/dist/components/Card.js");
};

export default {
  "card renders": async ({ pass, fail }) => {
    const card = document.createElement("k-card");
    card.label = "Test";
    document.body.appendChild(card);
    await card.updateComplete;
    if(card.shadowRoot.querySelector("slot")) pass();
    else fail("No slot found");
    card.remove();
  }
};
```

**IMPORTANT:** No top-level imports with `/framework/` or `/modules/` paths — use dynamic `import()` in `beforeAll`.

Node test files (`.node-test.js`): same test signature, no `page` export needed.

Lifecycle hooks: `beforeAll`, `afterAll`, `beforeEach`, `afterEach` (all optional).

Mock API: `window.__kempoTestDbStore` for direct db access in tests.

Run: `npx kempo-test`

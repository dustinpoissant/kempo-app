SQL Database

Import the DB class from the framework to access a SQL database powered by better-sqlite3. Each database name becomes a separate .db file. DB works in both the renderer process and backend.js — it auto-detects its environment.

Install

better-sqlite3 is an optional dependency — install it in your project if you need a relational database:

npm install better-sqlite3

If not installed, calling db.query() or any table method will throw an error.

Quick Start

Create the Schema
// schema/mydb/users.js
export default {
  name: {
    type: 'text',
    required: true
  },
  email: {
    type: 'text',
    unique: true
  },
}

See Schema for full schema documentation.

Import and use the DB Class

In a page script or backend.js, import and use DB the same way:

import DB from '/framework/src/renderer/utils/sqlDB.js'

const db = new DB('mydb'); // Initiate the database named "mydb"
const users = db.table('users'); // Initiate the users table

// Create a record
const record = await users.create({
  name: 'Alice',
  email: 'alice@example.com'
})
record.data // { id: 1, name: 'Alice', email: 'alice@example.com' }

// Get all records
const all = await users.getAll()
all[0].data // { id: 1, name: 'Alice', ... }

// first match, or null
const user = await users.get({id: 1}); 

// last by insertion order, or null
const last = await users.getLast();

// Update and delete via record
await user.update({name: 'Alicia'});
await user.delete();

DB Class

Create a DB instance for each database. Use db.query(sql) for advanced SQL operations like joins, aggregations, and subqueries — anything beyond basic CRUD. For creating, filtering, updating, and deleting records, use the Table and Record classes below.

Method Arguments Returns Description
new DB(name) Database name DB instance Opens (or creates) a .db file for the given name
db.query(sql) SQL string Array (SELECT) or true Run raw SQL for advanced queries (joins, aggregations, etc.)
db.table(name) Table name Table instance Get a Table for CRUD operations on a named table

Table

db.table(name) returns a Table instance. Methods that return a single row return a Record (or null); methods that return multiple rows return an array of Records.

Method Arguments Returns Description
create(data) Object with column values Record Insert a new row and return it as a Record
get(filter?) Optional filter object Record or null Return the first matching row, or null
getLast(filter?) Optional filter object Record or null Return the last row matching the filter (by insertion order), or null
getAll(filter?) Optional filter object Array of Record Return all matching rows as an array of Records
update(filter, data) Filter, update data true Update the first matching row
updateAll(filter, data) Filter, update data true Update all matching rows
delete(filter) Filter object true Delete the first matching row
deleteAll(filter) Filter object true Delete all matching rows

get() and getLast() order by SQLite's internal rowid, which reflects insertion order — not any column you define. So get() returns the first-inserted matching row and getLast() returns the last-inserted, regardless of your schema's primary key.

Record

Records are returned by table methods. Access the row via record.data; call update or delete directly on the record.

Member Arguments Returns Description
record.data — Object The row's current column values as a plain object
record.update(data) Object with updated column values true Update the row in the database and sync record.data
record.delete() — true Remove the row from the database

Backend Access

DB works identically in backend.js — import it the same way and use the same API. No IPC handlers needed. 

import DB from '/framework/src/renderer/utils/sqlDB.js';
export default async ({
  ipc
}) => {
  const users = new DB('myapp').table('users');
  ipc.handle('get-user', async (e, id) => {
    const record = await users.get({
      id
    });
    return record?.data ?? null;
  });
};

Storage Location

Each database is stored as a separate .db file:

Platform Path
Windows %APPDATA%\<appName>\db\*.db
macOS ~/Library/Application Support/<appName>/db/*.db
Linux ~/.config/<appName>/db/*.db

SQLite uses WAL (Write-Ahead Logging) journal mode for better concurrent read performance. Connections are cached and automatically closed when the app quits.
